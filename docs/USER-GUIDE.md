# Qivoryx — Windows Toolkit 0.3.0

Нативное приложение для Windows 10/11 **x64**, интерфейс на русском языке. Тёмная и светлая монохромные темы, собственная рамка окна, объёмные поверхности, единые выпадающие списки и тонкая прокрутка, плавная прокрутка страниц, переходы, индикаторы выполнения и уведомления. Portable не требует установленного .NET; установщик использует встроенный в Windows .NET Framework 4.8.

## Запуск

- **Portable:** распакуйте `Qivoryx-0.3.0-Portable-x64.zip` полностью, запустите `Qivoryx.exe`. Соседние файлы и папки нужны для работы.
- **Установка:** запустите `Qivoryx-0.3.0-Setup-x64.exe`. Установка для текущего пользователя в `%LOCALAPPDATA%\Programs\Qivoryx`, ярлык в Пуске и при выборе на рабочем столе. Удаление — через Параметры Windows или `Uninstall.exe`.
- Для обычного просмотра администратор не требуется. При изменении системных параметров приложение запрашивает UAC. Установка сторонних программ также может запросить UAC.
- Данные портативной версии: папка `Data` рядом с `Qivoryx.exe` (её можно перенести вместе с приложением). Маркер `portable.flag` включает этот режим. Папка приложения должна быть доступна для записи. Данные установленной версии: `%LOCALAPPDATA%\Qivoryx`. Если найдена папка данных предыдущей версии, она продолжает использоваться для сохранения журнала и отката; portable-версия всегда использует свою папку `Data`. Установщик не переносит личные данные из portable-сборки. Portable не регистрирует себя в системе; .NET может создать обычный кэш распаковки среды выполнения в TEMP.

## Возможности

**Обзор.** Реальные сведения WMI/CIM о CPU, памяти, дисках, времени работы и защите. Значения — снимок на момент обновления, не постоянный мониторинг.

**Центр оптимизации.** Реальная диагностика CPU, памяти, свободного места и процессов. CPU отдельных процессов снимается за секунду и нормируется на весь процессор; процессы можно смотреть по CPU или рабочему набору памяти. Рекомендации зависят от текущей нагрузки, а не искусственного «рейтинга оптимизации». Снимок можно сохранить и сравнить по памяти и числу процессов, но это не FPS-бенчмарк. Три анимации Windows (окна/клиентская область, меню, подсказки) выключаются отдельными системными API с резервной копией, проверкой результата и возвратом исходного значения. Если параметр изменён другой программой, откат не затирает его. Для накопителей — Optimize-Volume: Windows выбирает подходящую операцию по типу носителя. Для WinSxS — DISM StartComponentCleanup без ResetBase и автоматической перезагрузки; отдельный CheckHealth читает сохранённый флаг повреждений. Обслуживание не имеет собственного отката и запускается отдельно после подтверждения. Игровые функции и аппаратно зависимые настройки графики доступны через переходы в Windows.

**Тонкая настройка.** Задержка раскрытия меню 100 мс с сохранением уже более быстрого значения, линейное движение указателя, отключение встроенной записи игр и прозрачности Windows. Каждая настройка имеет описание условий полезности, текущее состояние и индивидуальный откат. Сохраняются точные исходные значения, включая отсутствие и тип записи реестра. Откат не затирает изменения, сделанные другой программой.

**Лаборатория кадров.** Импорт реальных CSV PresentMon, выбор конкретного процесса и swapchain, сравнение A/B, график времени кадра, средний FPS, 1% low, медиана и P95/P99, подсчёт длинных кадров. Формулы показаны в интерфейсе. Разные метрики не смешиваются; CPUFrameTime не выдаётся за интервал фактического вывода на экран. Локальная библиотека, экспорт HTML с графиками и нормализованного CSV. Запись CSV выполняется внешним инструментом; встроенного захвата кадров нет. Для достоверного сравнения повторяйте одинаковую сцену, настройки игры и длительность, сделайте несколько проходов.

**Игровые сессии.** Запуск выбранного EXE или подключение к собственному процессу, временный выбор существующего плана питания и, по желанию, приоритет AboveNormal. Возврат исходного плана после выхода или завершения сессии. Чужие изменения сохраняются. После аварийного закрытия доступно восстановление сохранённого состояния. Отслеживается выбранный процесс, а не автоматически все дочерние игры лаунчера. Повышение приоритета не обещает прироста FPS и может влиять на фоновые задачи. Запись восстановления сессии, в том числе в portable-режиме, хранится в `%LOCALAPPDATA%\Qivoryx\Sessions` и защищена Windows DPAPI; после аварийного закрытия временные параметры возвращаются при следующем запуске приложения, а не мгновенно.

**Графика и дисплей.** Сведения о видеокартах AMD/NVIDIA/Intel, драйверах, подключённых дисплеях и режимах. Выбор поддерживаемой частоты без смены разрешения с тестом режима и временным предпросмотром: без подтверждения возвращается прежняя настройка. Индивидуальные рекомендации по задержке и плавности для AMD/NVIDIA и переходы в официальные панели. Поддержка конкретных технологий зависит от GPU, драйвера, монитора и игры. Для известных асимметричных Ryzen 9 X3D есть проверка Game Bar, Game Mode и 3D V-Cache Optimizer, а также пояснения о парковке ядер в разделе питания и при удалении Game Bar. Модели с другой топологией не объявляются совместимыми автоматически.

**Автозагрузка.** Записи Run текущего пользователя/компьютера x64/x86 и личной/общей папок Startup. Поиск, просмотр исходной команды, отключение выбранной записи с копией и возврат без запуска программы. По возможности учитывается отметка отключения в Диспетчере задач. Защитные компоненты не предлагаются к отключению; службы и задания планировщика не смешиваются с обычной автозагрузкой. Отключение влияет на следующий вход, не закрывает работающий процесс и не удаляет программу. При конфликте с новой записью восстановление не перезаписывает её. Личные копии привязаны к SID пользователя и компьютеру. Копии общих записей хранятся отдельно в `%PROGRAMDATA%\Qivoryx\StartupMachine` с защищёнными ACL (Administrators/SYSTEM — полный доступ, Users — чтение), включая файлы и исходные ярлыки; существующий каталог с неподходящими правами не используется. Перенос portable-папки сам по себе не переносит эти системные копии на другой ПК.

**Службы.** Все службы `Win32_Service`, поиск по имени и описанию, запуск, остановка и тип запуска. Для распространённых служб есть рекомендации; для остальных — описание Windows и отметка об отсутствии персональной рекомендации. Нагрузка показана для процесса-хоста; если он общий, цифры повторяются и не являются отдельным потреблением каждой службы. Критические службы защищены от изменений. До каждого изменения сохраняется JSON с типом запуска, отложенным запуском и состоянием; восстановление доступно в журнале. Драйверы не выдаются за службы приложений.

**Питание для настольного ПК.** Десять настроек CPU, парковки, EPP, Boost, охлаждения, PCIe, USB, диска и экрана. Без выбора батареи: редактируются параметры работы от сети. Есть описание каждого параметра и влияния на FPS/плавность. Игровой профиль задаёт минимум CPU 5%, максимум 100%, Boost 1, EPP 0 и активное охлаждение там, где параметры доступны; USB, PCIe и парковку профиль не меняет. Применение создаёт копию исходного плана; при ошибке новый план удаляется и включается исходный. Есть возврат к предыдущему плану. Поддержка зависит от оборудования и Modern Standby; цифры прироста FPS не обещаются. При нехватке поддержки параметра он недоступен в интерфейсе.

**Установка программ.** 126 записей в 10 категориях: мессенджеры, IDE, браузеры, плееры/кодеки, дизайн, офис, игры, утилиты, облако/сеть, безопасность. Выбор нескольких программ и последовательная очередь, ошибки записываются в журнал. Сначала `winget install --exact --silent` из источника winget. Для всех 126 записей есть запасной HTTPS-источник: URL, версия, SHA-256, тип и тихие ключи взяты из выбранного официального манифеста `microsoft/winget-pkgs`. В каталоге сохранена ссылка `Manifest`. При отсутствии/ошибке winget скачивается файл, сверяется SHA-256, затем запускается подходящий EXE/MSI/MSIX или извлекается ZIP. Выход за границы папки распаковки запрещён. Для пользовательских расширений каталога предусмотрена также проверка Authenticode вместо SHA-256. Portable-утилиты сохраняются в `Programs` внутри папки данных, получают ярлык в Пуске и видны в списке удаления Qivoryx; глобальный PATH не меняется. Прямые версии зафиксированы на момент сборки, тогда как winget получает актуальный пакет. Если издатель заменит/удалит файл, каталог нужно обновить; несовпадение хеша отменяет запуск. Отдельные пакеты могут требовать установки зависимостей или лицензии. Winget `--silent` не подавляет UAC, обязательные диалоги ОС и перезапуск, заданный сторонним установщиком. Для установки приложение принимает соглашения выбранных пакетов после подтверждения пользователя. В каталоге можно включить повышение прав для системных установок; пользовательским пакетам оно обычно не требуется.

**Удаление.** Реестр Win32 HKLM/HKCU, x86/x64 и Appx текущего профиля, включая зарегистрированные кодеки, Microsoft Store и пакеты библиотек. MSI и QuietUninstallString запускаются тихо; когда тихая команда не зарегистрирована, показывается штатный деинсталлятор. Используется текущая команда из реестра, а не произвольная команда интерфейса. Защищённые Appx не вырезаются вручную. Edge — отдельная кнопка запуска штатного setup, результат проверяется. На части сборок и регионов удаление запрещено; Windows Update может вернуть Edge. WebView2 сохраняется. Приложения чужих профилей, незарегистрированное портативное ПО, драйверы и компоненты CBS не представлены как удаляемые программы. Список не может буквально охватывать все файлы и компоненты Windows.

**Очистка.** Предварительный анализ и выбор: TEMP текущего пользователя, Windows\Temp, D3DSCache, CrashDumps. Только файлы старше 48 часов; занятые файлы и ссылки пропускаются. Загрузки, документы, cookies, пароли и корзина не затрагиваются. Кэш шейдеров не выбран по умолчанию: после очистки возможна временная перекомпиляция и подёргивания игр. Для остальных дисков и системного хранилища есть переход в Параметры Windows. Удаление необратимо.

**Defender.** Интеграция исходного архива пользователя `DefenderKiller.7z`. Файлы извлекаются в `Integrations\DefenderKiller` без изменений; перед запуском сравниваются SHA-256 с манифестом сборки (это проверка целостности относительно поставки, не независимая проверка безопасности). Кнопка после отдельного подтверждения запускает BAT с `/DelWD` и UAC. Меню удаления выбирать не нужно. **Запуск видимый:** несмотря на заявленный автором тихий аргумент, BAT содержит диалоги резервного копирования и паузы; скрывать их означало бы риск зависания. Скрипт удаляет также SmartScreen и дополнительные компоненты защиты. Неизвестные native-помощники не проходили аудит исходного кода. Qivoryx не утверждает, что Defender удалён, по одному коду выхода BAT. Результат и перезагрузку нужно проверить отдельно. Автоматический откат Defender не реализован; исходный инструмент содержит своё восстановление. Не удаляйте его файлы до завершения всех операций и перезагрузки. Распространение третьестороннего инструмента отдельно требует проверки лицензий его авторов.

## Проверка и ограничения

В рабочей системе проверяются чтение данных, сборка и отрисовка всех страниц в обеих темах. Удаление Defender/Edge/программ, очистка файлов и изменения служб/питания **не исполняются для теста на пользовательском ПК**. Перед использованием этих операций необходима проверка на виртуальной машине с нужной сборкой Windows и резервной копией. Это версия 0.3.0, а не гарантия совместимости со всеми сборками и сторонними деинсталляторами. Сборки не подписаны коммерческим сертификатом.

## Сборка из исходников

Требуются Windows x64, PowerShell 7, .NET SDK 8 и CLI `7z`. Оригинальный `DefenderKiller.7z` должен лежать рядом с `build.ps1`.

```powershell
pwsh -File build.ps1
```

Локальный SDK в `.tools\dotnet` используется автоматически, иначе берётся `dotnet` из PATH. Установщик и деинсталлятор компилируются встроенным компилятором .NET Framework, без установки стороннего упаковщика. Исходники приложения — `Tweaker`, системный обработчик — `Tweaker\Backend.ps1`, упаковка — `Installer\Setup.cs`. Каталог редактируется в `Tweaker\catalog.json`; значок обновляется через `tools\brand_assets.py` (Pillow). Генератор `tools\generate_assets.py` пересоздаёт базовый каталог; после него нужно обновить прямые источники: `tools\sync_fallbacks.py` (PyYAML) читает `artifacts\installer-metadata.json`, сформированный из `winget show`, и сохраняет выбранные официальные манифесты. При обычной сборке `build.ps1` используется готовый каталог с прямыми источниками, Python не требуется.

Read-only UI-проверка: `Qivoryx.exe --smoke`. Она открывает окно вне экрана, читает данные Windows и сохраняет PNG всех 15 страниц в обеих темах, открытых списков, прокрутки и диалогов в `artifacts\ui` относительно рабочей папки сборки. Системные изменения не выполняются. Проверка распаковки установщика: `Qivoryx-0.3.0-Setup-x64.exe --verify <абсолютный-путь-отчёта>`; регистрация установки и ярлыки не создаются.

- Новое имя Qivoryx, новый значок, единое оформление приложения и установщика.
- Лаборатория кадров с A/B, библиотекой и экспортом отчётов.
- Игровые сессии с временными настройками и восстановлением.
- Раздел графики и дисплея с настройкой частоты и рекомендациями AMD/NVIDIA.
